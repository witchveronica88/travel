# 사진 넣기 안내 (뮤즈용)

뮤즈가 맡는 일은 **사진이 없는 카드에 무료 사진을 넣는 것 하나뿐**이다.
글 · 일정 · 시각 · 지도 링크 · 카드 순서는 고치지 않는다. 고칠 게 보이면 고치지 말고 사용자에게 알린다.

대상은 `istanbul/index.html`이다. 해남(`haenam/`)도 같은 방법으로 넣는다.

---

## 0. 시작 전에

1. 최신으로 받는다: `git pull origin main`
   - 다른 세션도 같은 파일을 고친다. 작업 전과 커밋 전에 꼭 받는다.
   - 강제 푸시(`--force`)는 하지 않는다.
2. `index.html`은 사진 때문에 3MB가 넘는다. **통째로 열지 않는다.**
   - 볼 때는 사진 글자를 지우고 본다.
     ```
     sed -E 's#data:[a-z]+/[a-z+]+;base64,[A-Za-z0-9+/=]+#DATA#g' istanbul/index.html > /tmp/plain.html
     ```
   - 사진 데이터는 문서 맨 끝 `<script>` 안의 `__setImgs([...])` 한 줄에 모여 있다.
   - 앱 스크립트에는 사진 대신 `"data:,번호"` 같은 임시 주소만 있다. 이 구조 덕분에 일정이 먼저 뜨고 사진은 뒤따라온다.

## 1. 사진 없는 카드 찾기

```
NODE_PATH=/opt/node-tools/node_modules node .claude/skills/travel-page/photos.js istanbul
```

목록이 두 묶음으로 나온다.
- 사진이 안 뜨는 일정 카드
- 사진 칸이 없는 장소 · 맛집 · 음식 카드

`--used`를 붙이면 이미 쓰는 사진 목록도 나온다.

**넣는 순서**
1. 오늘 이후 일정 카드
2. 그 카드 아래 ＋ 줄로 붙은 장소 · 맛집 카드
3. 나머지 장소 · 맛집 카드
4. 음식 카드

**일정 카드는 대부분 장소 카드에 넣으면 해결된다.**
- 일정 카드는 자기 장소(`placeId`)나 ＋ 줄로 붙은 카드 가운데 사진이 있는 첫 카드의 사진을 쓴다.
- 그러니 ＋ 줄의 장소 · 맛집 카드에 사진을 넣는 게 먼저다.
- 연결된 카드가 없을 때만 일정 카드에 `photos`를 직접 넣는다.

**카드마다 넣는 사진**
| 카드 | 넣는 사진 |
|---|---|
| 점심식사 · 저녁식사 카드 | 그 지역 대표 음식 사진을 `photos`로 직접 넣는다(예: 괴레메 저녁 → 테스티 케밥). 특정 식당 사진은 메인 카드에 쓰지 않는다 |
| 호텔 도착 · 숙소 복귀 · 체크아웃 카드 | 이미 있는 숙소 사진을 다시 쓴다. 새로 받지 않는다 |
| 집 출발 · 집 도착 · 정류장 · 공항 도착 카드 | 넣지 않는다 |

## 2. 사진 고르기

- **위키미디어 커먼스(commons.wikimedia.org)의 사진만 쓴다.**
  - 라이선스는 CC0 · 퍼블릭 도메인 · CC BY · CC BY-SA만 쓴다.
  - 구글 지도 · 블로그 · 인스타그램 · 업체 홈페이지 사진은 쓰지 않는다. AI로 만든 사진도 쓰지 않는다.
- 그 장소를 실제로 찍은 사진을 고른다. 가로 사진, 낮 사진, 흐리지 않은 것이 좋다.
- 가게 사진이 없는 식당은 대표 음식 사진을 쓴다. 투어 상품(승마 · 하맘)은 체험 모습 사진을 쓴다. 이렇게 예시로 넣은 사진은 설명 끝에 `(예시 사진)`을 붙인다.
- 같은 사진이 이미 페이지에 있으면 새로 받지 않고 그 번호를 다시 쓴다(`photos.js --used`).
- 커먼스 API를 부를 때는 이렇게 한다.
  - `User-Agent`를 꼭 붙인다(예: `FamilyTravelPage/1.0`).
  - 요청 사이에 4~8초 쉰다.
  - `too many requests`가 나오면 몇 분 기다렸다가 다시 한다.
  - 가로 400px 썸네일 주소는 `prop=imageinfo&iiprop=url|extmetadata&iiurlwidth=400`의 `thumburl`이다. 라이선스는 `LicenseShortName`, 작가는 `Artist`에 있다.

## 3. 파일에 넣기

### ① 사진을 줄여 페이지에 넣는다 (도우미 스크립트)

```
python3 .claude/skills/travel-page/addphoto.py istanbul 받은사진.jpg
```

- 가로 400px WebP로 줄인다. 한 장이 60KB를 넘지 않게 한다.
- `__setImgs` 배열 맨 끝과 `I` 배열 맨 끝에 한 칸씩 붙인다.
- 마지막에 카드에 쓸 번호를 `I[160]`처럼 알려 준다.

스크립트를 쓸 수 없으면 손으로 같은 일을 한다.
1. `__setImgs([...])` 배열 맨 끝에 `"data:image/webp;base64,…"`를 붙인다. 0부터 센 그 자리 번호가 N이다.
2. `const I=[...]` 배열 맨 끝에 `"data:,N"`을 붙인다. 그 칸의 번호가 K다.
   - 지운 사진 자리가 있어서 K와 N은 다를 수 있다(예: `I[159]` = `"data:,164"`).

### ② 받은 번호 `I[K]`를 카드에 연결한다

| 카드 | 넣는 곳 | 모양 |
|---|---|---|
| 장소 카드 `place({id:"…"})` (맛집 탭의 `place({tab:"맛집"})`도 같다) | `const PHOTOS = {` 안, `const PHOTO_ALTS = {` 안 | `"cap-sunsetview":I[K],` · `"cap-sunsetview":"괴레메 마을 너머로 보이는 바위 계곡",` |
| 맛집 카드 `wishlistRestaurant({…})` | 카드 맨 끝 `map:…` 뒤 | `,photo:{src:I[K],alt:"…"}` |
| 음식 카드 `food({…})` | 카드 맨 끝 | `,photo:{src:I[K],alt:"…"}` |
| 일정 카드 `s("시각","제목",{…})` | `{` 안 | `photos:[{src:I[K],alt:"…"}],` |

id가 `cap-about`처럼 `-`를 품으면 따옴표로 감싼다.

### 하면 안 되는 것
- **앱 스크립트에 base64를 직접 넣지 않는다.** 첫 화면(오늘 일정)이 느려진다.
- **`I`와 `__setImgs`의 기존 칸을 지우거나 순서를 바꾸지 않는다.** 다른 카드 사진이 뒤바뀐다. 사진을 빼야 하면 카드와의 연결만 지운다.
- 사진 말고 다른 글·데이터는 건드리지 않는다.

## 4. 사진 설명(alt)

- 무엇이 보이는지 한국어 한 줄로 쓴다(예: `로즈 밸리 전망대에서 본 카파도키아 계곡`).
- 그 장소가 아닌 예시 사진이면 끝에 `(예시 사진)`을 붙인다(예: `항아리에 담겨 나온 테스티 케밥 (예시 사진)`).

## 5. 출처 적기

`istanbul/photo-credits.md` 표에 한 줄 더한다.
```
| 쓴 곳(카드 이름) | Commons 파일 이름 (작가) | 라이선스 |
```
CC BY · CC BY-SA 사진은 작가 이름을 꼭 적는다.

## 6. 확인

1. 점검에 경고가 0개인지 본다.
   ```
   NODE_PATH=/opt/node-tools/node_modules node .claude/skills/travel-page/audit.js istanbul
   ```
2. `photos.js`를 다시 돌려 넣은 카드가 목록에서 빠졌는지 본다.
3. 휴대폰 폭(360px)으로 화면을 찍어 사진이 제자리에 뜨는지 본다. 다크 모드에서도 본다.
4. 사진을 여러 장 넣었으면 느린 통신(4Mbps, CPU 4배 느리게)에서 첫 일정이 1~2초 안에 뜨는지 잰다.

## 7. 올리기

1. `git pull origin main`으로 다시 받는다.
2. `main`에 바로 커밋하고 푸시한다. 브랜치나 PR은 만들지 않는다.
3. 커밋 메시지는 `이스탄불: 사진 추가 (선셋 전망대 · 아바노스 · Seten)`처럼 넣은 카드를 적는다.
4. 몇 분 뒤 `https://witchveronica88.github.io/travel/istanbul/`에서 사진이 뜨는지 본다.
